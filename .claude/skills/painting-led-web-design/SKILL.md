# 名画から作る Web デザイン

このスキルは、StudyReel の LP の作例（`public/works/studyreel-parasol.html`）を作ったときのやり方と、そこで受けたフィードバックを、次の作業で使える形にまとめたもの。経緯と、すべての判断の記録は `references/case-studyreel.md` にある。

## いちばん大事な決まり

**変更には、理由・根拠・例・反例を必ずつける。** フィードバックも、そのまま採用も却下もしない。根拠を探して、肯定か否定かを決める。

- 根拠の強さを書き分ける：**測定**（自分で測った値・検定）／**基準**（WCAG・web.dev・JLREQ など）／**研究**／**事例**（実在のサイトや作品）／**推測**（根拠なし）
- 根拠がなければ「根拠なし」と書く。原則の名前を並べて、根拠があるように見せない
- 比べるときは 1 回の測定で決めない。10 回ずつ測り、並べ替え検定か Mann-Whitney の U 検定で判断する（`scripts/stats.py`）。差が出なかった変更は戻す（効果のない仕組みを残さない）

## 手順

1. **製品を調べる。** 機能・文言・色・字体を、リポジトリのコードと App Store の説明文で確かめる。書くことはすべて、ここで確かめた事実に限る
2. **絵を選ぶ。** 色ではなく、製品の「気分」で選ぶ。パブリックドメイン（作者の没後 70 年以上）の作品だけを使う
3. **絵を測る。** `python3 -I scripts/measure_painting.py 画像` で、代表色（面積つき・OKLCH）、明るさの分布、暖色と寒色の割合を出す。型は `references/color-patterns.md`
4. **借りるのは値ではなく関係。** 明るさの並び順と差、暖かさと冷たさ、面積の比率を借りて、画面の明るさの範囲に写す（`references/rules.md` の 1 章）
5. **コンセプトをページの構造にする。** 部品を飾るのではなく、ページ全体で絵を表す（例：タイムラプスのアプリなら、ページ全体を昼から夜へ移る一枚の空にする）
6. **製品の画面は、コードから再現する。** スクリーンショットを貼らず、色・文言・寸法をコードの値どおりに HTML で組む。「画面はアプリを再現したイメージです」と、最初の画面のすぐ近くに書く（誤認させない）
7. **人間は描かない。** SVG を手で書いて人間の顔や体を描くと、完成度が落ちる。単純な形のキャラクターにする
8. **文言は、使う人を主語にする。** 見出しは使う人の行動を動詞で書く。言葉遊びは、文字どおりに読んでも意味が通るものだけ使う（`references/rules.md` の 4 章）
9. **写真を入れるなら、生成用のプロンプトも渡す。** 入れるかどうかの判断も根拠で決める（`references/photo-prompts.md`）
10. **検査して、合格するまで直す**（下の表）

## 合格基準と検査

ページは完全な HTML として、作業フォルダに置いてから検査する。スクリプトは Playwright を使う（`require('playwright')`）。

| 項目 | 基準 | 検査 |
|---|---|---|
| 横スクロール | 360 / 390 / 768 / 1280 / 1920px で 0 | `node scripts/check.js page.html` |
| タップ領域 | 44×44px 以上（文中のリンクは除く） | 同上 |
| 見出しの泣き別れ | 2 文字以下の行を作らない | 同上 |
| 図のラベル | 意味のある図には `role="img"` と `aria-label`、飾りは `aria-hidden` | 同上 |
| コンソールのエラー | 0 | 同上 |
| 動きを減らす設定 | アニメーションが 0 | 同上 |
| 文字のコントラスト | WCAG 1.4.3（本文 4.5:1、大きい文字 3:1）。絵の上の文字は、背景の実際の画素で測る | `node scripts/contrast.js page.html 1280 > c.json && python3 -I scripts/crcheck.py c.json`（390 でも） |
| 文章 | textlint 0 件 | `npx textlint --config scripts/textlintrc.json`（textlint 15 以上、`textlint-plugin-html`、`textlint-rule-preset-ja-technical-writing`、`@textlint-ja/textlint-rule-preset-ai-writing`、`textlint-rule-preset-ja-spacing`） |
| 性能 | Lighthouse の性能 90 以上（スマホ、10 回の中央値）。TBT 200ms 未満 | `npx lighthouse URL --only-categories=performance` を 10 回。比較は `scripts/perf.js` と `scripts/stats.py` |

再現した製品の画面の中の文字は、WCAG 1.4.3 の例外（重要な視覚的内容を含む画像の一部になっている文字）として扱ってよい。製品の色に忠実であることを優先する。

## 性能で分かったこと（測定済み）

- 日本語の Web フォントは細かく分割されて届き、届くたびに文書全体のレイアウトが組み直される。**使う文字だけの字体を読み込む**（`scripts/fontlinks.py` が Google Fonts の `text=` を作る）。製品の画面の再現は**システムの字体だけ**で組む（TBT の中央値 397→154ms、p=0.015）
- 背景の絵を canvas で描くときは、**見える区間だけ／8ms ごとに区切る／字体の読み込みを待つ／画面に出ていない canvas に描いてから一度だけ写す**（Lighthouse 性能 84→88、p=0.022）
- 効果がなかったもの（入れない）：SVG の揺らぎフィルターを外す、画面外の画面を後から組み立てる、`content-visibility`、絵を画像に置き換える、canvas の解像度を下げる
- 1 回の測定は大きく揺れる。字体はキャッシュして同じ遅延で返し、10 回以上測る

## 写真について

装飾の写真は見られない（NN/g の視線計測）。情報を持つ写真（実在の人、実物の製品）だけ使う。入れるなら、生成用のプロンプトを一緒に渡す。詳しくは `references/photo-prompts.md`。
