# 名画からデザインするときのルール

絵から色の値をそのまま取ると失敗する。人は色を絶対値ではなく、周りとの関係で見ている。
借りるのは値ではなく関係（明るさの差、暖かさと冷たさ、面積の比率）にする。

## 1. 色は関係で見える

### 実測：「日傘をさす女」は、測ると暗くてくすんでいる

Wikimedia Commons の画像（Google Art Project、960px）を画素単位で測った値。色の近いものをまとめて、代表色を出した。

| 部分 | 見た目の印象 | 実際の画素 | OKLCH（明るさ L / 鮮やかさ C / 色相 h） |
|---|---|---|---|
| 右上の空 | 鮮やかな青空 | `#5B7A98` 前後 | L0.52〜0.60 / C0.06 / h248 |
| 雲の明るい部分 | 光る白 | `#DDD5C3` | L0.87 / C0.03 / **h87（黄み）** |
| 雲の影 | 青い影 | `#838991` | L0.63 / C0.01 / **h256（青紫）** |
| ドレスの上着 | 白 | `#7C8483` | L0.61 / C0.01 ← 実際は灰色 |
| 日傘 | 緑 | `#475843` | L0.44 / C0.04 |
| 下の草 | 濃い緑 | `#2B3528` | L0.32 |
| 絵全体の明るさ（中央値） | 明るい絵 | 相対輝度 0.21 | 実際は中くらいの明るさ |

この絵は、鮮やかさ（C）がどこも 0.07 以下と低い。それでも明るく鮮やかに見えるのは、次の関係があるから。

### 原則

1. **明るさの基準は、視野でいちばん明るいもの（アンカー）**
   美術館では、絵の中の雲がいちばん明るいので白に見える。Webページでは、下に続く白いセクションが基準になる。ヒーローのいちばん明るい色が、ページの白より暗いとヒーロー全体がくすんで見える。
   → ヒーローの光（雲）を、ページでいちばん明るい色にする。本文の背景は、それより少しだけ暗くする。

2. **光は暖かく、影は冷たく**
   モネの雲は、光の当たる部分が黄み（h87）で、影が青紫（h256）になっている。明るさの差ではなく、色温度の差で光を表している。
   影を灰色や緑寄りの灰色にすると、曇り空に見える（1回目の失敗はこれ）。

3. **同時対比：灰色は、隣の色の反対側に寄って見える**
   青の隣に置いた灰色は、黄み寄りに見える。だから灰色のドレスが「日に当たった白」に見える。
   → 背景を青にするなら、白は少し黄みに振るだけで十分に光って見える。

4. **並置混色：半透明で重ねると濁る**
   半透明の筆を重ねると色が平均され、灰色に寄る。不透明な色を隣に並べると、目の中で混ざってきらめいて見える。
   → 筆のタッチは、不透明に近い筆跡を並べて描く。

5. **暗い色は小さく、視線の入口近くに置く**
   この絵で暗いのは、上の方にある日傘と、画面の下の草だけ。暗い部分が小さく締まっているので、ほかの部分が明るく見える。
   大きくて暗いもの（1回目のスマホの黒いフレーム）は、画面に穴があいたように見える。
   → 暗い色は、ボタンなど小さい面積に使う。

6. **面積効果：同じ色でも、面積が大きいほど明るく鮮やかに見える**
   小さな色見本で選んだ色を広い面に塗ると、強く出すぎる。逆に、ボタンのように小さい面積の色は、少し強めでいい。

7. **明るくするときは、白を混ぜない**
   白を混ぜると、鮮やかさが落ちて粉っぽくなる。OKLCH で明るさ L だけを上げ、鮮やかさ C は保つ。

### やり方

1. 絵を画素単位で測り、部分ごとの代表色を OKLCH で出す
2. 明るさの「並び順」と「差」、色相の差（暖かい・冷たい）、面積の比率を記録する
3. 画面の明るさの範囲に写す。いちばん明るい色をページのアンカーにして、ほかの色は関係を保ったまま持ち上げる
4. 実際の画面で、周りの色と並べて確かめる。色見本を1色ずつ見て決めない

## 2. 文字

| 項目 | 基準 | 理由 |
|---|---|---|
| 本文の大きさ | 16px | スマホでも拡大せずに読める最小限の大きさ |
| 本文の行間 | 1.9 前後 | 漢字とかなは字面が四角いので、欧文より広い行間が必要 |
| 本文の字間 | 0.04em | 和文は、少し空けた方が読みやすい |
| 1行の文字数 | 30〜38字 | これより長いと、次の行の頭を目で探しにくくなる |
| 見出しの字間 | `palt` で詰めてから 0.04em | かなの左右の余白を詰めないと、間延びして見える |
| 見出しの行間 | 1.4〜1.5 | 大きい文字は、行間の比率を下げても窮屈に見えない |
| 大きい見出しの太さ | 細めにする（500） | 大きい文字ほど太く重く見える。明るい画面で太字にすると、そこだけ黒い塊になる |
| 文字サイズの段 | 比率 1.25 で 5〜6段（13 / 16 / 20 / 25 / 31 / 49px） | 段の数を絞ると、文字の大きさの差がそのまま情報の階層になる |
| 改行の位置 | 文節で切る。1文字だけの行を作らない | 「タイムラプ／ス」のような切れ方は、読むリズムが止まる |
| 数字 | 欧文の書体に揃える | 和文書体の数字は、幅も形も揃っていないことが多い |

## 3. 余白とバランス

- 余白は 8px を単位にする（8 / 16 / 24 / 40 / 64 / 112）
- 余白の比率は「見出しと本文」:「段落の間」:「セクションの間」= 1 : 2 : 6〜7 くらいにする。関係の近いものほど近くに置く
- 見た目の重さは、暗さ × 面積 × 鮮やかさで決まる。重いものを片側に寄せたら、反対側には余白か、小さくて強いものを置いて釣り合わせる
- 物は地面に置く。宙に浮いた要素は落ち着かない（1回目のスマホは草の上に浮いていた）
- 英字の小見出し（FEATURES など）や番号は、情報があるときだけ使う。番号は、実際に順番がある手順にだけ振る

## 4. 言葉

### AIっぽさの正体は、組み立て方にある

| パターン | 例（1回目の文） | 直し方 |
|---|---|---|
| 決め台詞のような見出しが続く | 「やることは、三つだけ。」「もっと深く、自分の勉強を知る。」 | 見出しは、セクションの中身の名前でいい（使い方、できること） |
| 三つ並べ | 「撮る、測る、見返す。」 | 本当に3つあるときだけ使う。リズムのために並べない |
| 無理な比喩 | 「積み上げた日が、空の色で残る。」 | 起きることをそのまま書く（勉強した日は、カレンダーに色がつく） |
| 呼びかけで締める | 「〜しましょう」 | 事実で終える。呼びかけは最後の1回だけにする |
| どの見出しにも句点がある | 「〜知る。」 | 見出しに句点は付けない |
| 書き手側の言葉 | 「記録として積み上がります」 | 読み手が実際にする動作や、目にするもので書く（スマホを立てる、早送りの動画） |

### 書くときの基準

- 1文に情報は1つ。40〜60字以内
- 読み手に合わせた温度で書く。受験生向けなら、少しくだけた話し言葉でいい
- 事実は具体的に書く。確かめられない数字（〇秒の動画、〇%向上など）は書かない
- サンプルのデータには、サンプルと書く

### ツール

- textlint + `textlint-rule-preset-ja-technical-writing` + `@textlint-ja/textlint-rule-preset-ai-writing`（textlint 15 以上）
- 限界：ツールで見つかるのは、表記の揺れ・数字の書き方・決まった言い回しまで。上の表のような組み立て方のAIっぽさは、ほとんど検出できない（1回目の文章は、AI向けのルールで0件だった）。最後は表を見ながら人の目で確かめる

## 5. 相対的な見え方を「使う」（2回目のフィードバックから）

色を相対的に計算して、その値を置くだけでは足りない。**見え方が変わる場面をページの中に作る**。

- 同じ色を、違う背景の上に置く。例：くすんだ灰色のカードを青い帯の中に置くと、白く見える。白の上に置くと灰色に見える。カードに真っ白を使うより、ページに深みが出る
- 暗い面は1か所だけにして、その上で明るい色を光らせる。例：勉強時間のカレンダーを日傘の緑の上に置き、勉強した日ほど明るい色にする。暗い面の上では、明るい色が光って見える
- 灰色に色みを足しすぎない。青の中では灰色が勝手に黄みに寄って見えるので、最初から黄みにすると、ベージュに見えてしまう（実際に失敗した）
- 最初と最後だけでなく、中盤のセクションにも絵の色の帯を通す。セクションの境目は線を引かず、上下の色を混ぜた筆跡でつなぐ

## 6. 中盤の作り込み

- セクションごとに組み方を変える。どのセクションも「見出し → 説明 → カード」の同じ型にしない
- 見出しの大きさは中盤でも落とさない（39px）。小さい見出しが続くと、途中のページが資料のように見える
- 大きな数字は、背景に近い色で薄く置く。読ませるためではなく、リズムを作るため
- 余白は、セクションの上に広く（160px）、下はそれより狭く（104px）とる。次の見出しの前で間ができて、区切りがはっきりする

## 7. 言葉の調子

説明口調（〜できます、〜されます、の繰り返し）は、資料の文章になる。実際のLPは、次のように書かれていることが多い。

- 見出しは短く、場面か気分を書く（「机の上の3時間を、早送りで。」）
- 説明は1〜2文。語尾をそろえず、体言止めや「〜だけ」を混ぜる（「裏のバーコードを読むだけ。」）
- 機能名より、使う人の行動を書く（「科目や参考書もここで選べます」）
- ただし、決め台詞の見出しばかり続けると、AIっぽくなる。中身の名前（「使い方」）は小見出しのラベルに回して、見出しでは気分を書く

## 8. プロの原則から（3回目：調べたうえでの改善）

### 見出しには句読点を付けない

- 広告の見出しは、戦前から句読点を省く習慣がある（[koubo.jp](https://koubo.jp/article/57962) など）。見出しは「読ませる文字」ではなく「見せる文字」として扱う（[マイナビ MacFan の和文組版の記事](https://macfan.book.mynavi.jp/article/m72243)）
- 組版上の理由：大きな見出しでは、「、」「。」が文字1つ分の箱を使うのに、中身はほとんど空白になる。行末に穴があいたように見えて、見出しの右端がガタつく
- 区切りは句読点ではなく改行で入れる。本文は文章なので、句読点を付ける

### 強調は大きさではなく、太さと色でつける（Refactoring UI）

- 主役のボタンは1画面に1つ。2番目以降はリンクの見た目にする
- 大きい文字ほど、字間と行間を詰める（見出し 0.01〜0.03em / 1.3〜1.5、本文 0.04em / 1.9）
- 線で区切らず、余白と面の色の差で区切る

### 視線を集める場所だけ、輪郭をくっきりさせる（found edge / lost edge）

- 絵画では、焦点の場所だけ輪郭をくっきりさせ（found edge）、それ以外はぼかす（lost edge）
- Webに置き換えると、主役のボタンだけ角を立てる（角丸 3px、単色）。カードやセクションの境目は、角を大きく丸めたり筆跡でつないだりして、ぼかす
- 1回目の、筆跡の質感が入った不定形のボタンは、焦点なのに輪郭がぼやけていた。これは逆の使い方だった

### 白黒（ノタン）で確かめる

- ページを白黒にしてぼかし、いちばん暗い面とコントラストの強い場所が、見てほしい場所（見出しとボタン）に集まっているか確かめる
- 確かめ方：Playwright で `filter: grayscale(1) blur(3px)` をかけて撮影する

### 色の相対性（アルバース『色彩構成』）

- 「1つの色が2色に見える」「違う2色が同じに見える」は、アルバースの演習の基本（[Albers Foundation](https://www.albersfoundation.org/learning/workshops/one-color-becomes-two)）
- ページの中で、同じ色を違う背景に置く場面を、意図的に作る

## 9. 言い過ぎない（4回目：日本の文脈）

### 背景

- 文化人類学者エドワード・T・ホールの分類では、日本は高コンテクスト文化（意味を言葉の外の文脈に預ける）、アメリカは低コンテクスト文化（意味を言葉で全部言う）の典型とされる。広告でも、低コンテクスト文化では論理と説得、高コンテクスト文化では象徴と間接的な表現が多いと言われる（[Kirkwood Pressbooks](https://kirkwood.pressbooks.pub/emcworthy/chapter/cultural-dimensions/)）。ただし国単位の二分法には、学術的な批判もある
- 無印良品の考え方は、「これがいい」ではなく「これでいい」。原研哉はこれを「エンプティ（空っぽ）」と呼び、受け手が自由に解釈できる余白を残す。2003年の地平線の広告には、商品も呼びかけもなかった（[無印良品](https://www.muji.com/jp/flagship/huaihai755/archive/hara.html)）
- AIの文章は、英語のLPの型（機能を並べる、比べて勝つ、全部言う）を日本語に直訳したものになりやすい

### AIっぽい言い回し（構造）

| 型 | 例 | 問題 |
|---|---|---|
| 〜して〜する | スマホを立てて、シャッターを押す | 手順の説明になっていて、コンセプトになっていない |
| 〜するだけで〜できる | 押すだけで記録できる | 便利さの売り込み。比べて勝とうとする英語圏の型 |
| 機能のカードを並べる | できること×6 | 1枚ごとに文脈が切れる。見る前に全部わかってしまう |
| 他との違いを言い切る | もっと〜、〜より | 競争の言葉。読む人が身構える |

### 書き方

- 最初は「何ができるか」ではなく、一言の言い切り（「勉強を撮る」）。説明は小さな添え書きに回す（「iPhone の勉強記録アプリ」）
- 機能は、絵（コマの並び、光るカレンダー、灯り）に語らせる。文章は、その絵の題くらいの長さにする
- 細かい機能は、最後に「ほかにも」で一行に並べる。詳しくは使ってから知ってもらう
- 「いいんじゃない？」くらいで止める。言わなさすぎると何のページか分からないので、何のアプリかは必ず一度だけ書く
- 作り手の説明（このページの色の話など）は、折りたたんでおく。気になった人だけが開ける

### 箱で切らない

- カードを並べると、価値の流れが1枚ごとに切れる。セクションは一本の流れにする（このページなら、昼の空 → 夕方から夜の机 → 夜の灯り → 夕暮れ）
- 連作のアイデア：モネは積みわらや大聖堂を、時間を変えて何枚も描いた（[Wikipedia: Haystacks](https://en.wikipedia.org/wiki/Haystacks_(Monet_series))）。タイムラプスも「同じ机、ちがう時間」。机・ノート・人は全コマ同じ色にして、まわりの光だけ変えると、色の相対性がそのまま見せ場になる

## 10. SVG素材（5回目）

- 素材はページ先頭のSVGスプライト（`<symbol>`）にまとめ、`<use>` で使い回す。同じ絵を何度も描かない
- 絵の色は symbol の中に固定せず、CSS変数（`--wall` `--desk` `--lamp-a` など）で外から渡す。CSS変数は `<use>` の中まで継承されるので、1枚の机の絵から「16:00〜23:30の6コマ」「友達の机4つ」「スマホの画面」を作れる
- 変える色と変えない色を分ける。人・ノート・マグは全部のコマで同じ色にして、光の色だけを変える。こうすると色の相対性が、そのまま見せ場になる
- 手描きの揺らぎは `feTurbulence` + `feDisplacementMap` で少しだけ足す（scale 1〜3）。強くすると、ただの歪みに見える
- アイコンは 24px の枠に、線の太さ 1.6、端を丸くしてそろえる。色は日傘の緑の1色だけ
- 小さなアイコンで意味を伝えきれないときは、本文中の絵を使い回す（ランプのアイコン → 灯りのついた机の絵）
- 状態の違いは、絵の中の変数で表す。勉強中は `--lamp-a` で灯りをつけ、離席中は `--who:0` で人を消す

## 11. 部品ではなく、ページ全体を見る（6回目）

- 指摘された部品だけを差し替えていると、構成の問題が残る。毎回、ページ全体を白黒・縮小で見て、「同じ型のセクションを縦に積んでいないか」「絵らしいのは最初と最後だけになっていないか」を確かめる
- コンセプトを、ページの構造そのものにする。タイムラプスのアプリなら、ページ全体を「昼から夜へ移る一枚の空」にする（ページそのものがタイムラプスになる）
- 製品のLPでは、本物の画面を使う。作った絵は、本物の画面では見せられないもの（時間の流れ、気分）にだけ使う
- キャラクターは、製品の中のキャラクターに合わせる。モザイクのような制約は隠さず、絵の文脈に重ねる（原画で顔を覆うヴェール ＝ アプリの顔のモザイク）
- 区間ごとに canvas を分けるときは、色を区間の中の位置ではなく、ページ全体での位置（t）で決める。境目は、筆跡だけを上下にはみ出させて溶かす
- 色相をまたいで補間すると途中で緑を通るので、OKLab の a・b で補間する

## 12. 変更には、理由・根拠・例・反例をつける（7回目〜、最優先のルール）

- フィードバックは参考にするが、そのまま採用も却下もしない。根拠を探して、肯定か否定かを決める
- 変更ごとに次の4つを書く：**理由**／**根拠**（出典）／**例**（その判断を支える実在の事例）／**反例**（逆の判断をしている実在の事例）
- 根拠の強さを書き分ける：検証済み（研究・データ・自分のテスト）／事例（他社の実物）／推測
- 根拠が見つからないときは「根拠なし」と書く。原則の名前を並べて、根拠があるように見せない

### 文言（読み手の立場をそろえる）

- 立場：すべての見出しで、**使う人（受験生）が主語**、動詞は使う人の行動にする。見出し6つのうち、使う人が能動の動詞の主語になっている数：1 → 6
- 根拠：Burnkrant & Unnava (1995)：読み手が自分ごととして読める書き方は、メッセージの内容が強いときに説得力を上げる。ただし、強くしすぎると逆効果（後続の研究）
- 反例：Studyplus の小見出しは、名詞止めでアプリの側から書いている（「切磋琢磨できる　学習タイムライン」）
- 言葉遊び：McQuarrie & Mick (2003)：言葉の技法（韻、対句、掛詞など）を使った広告は、思い出されやすく、好まれやすい。ただし、文字の技法の効果は、しっかり読む条件でだけ出た。反例：Konovalova & Petrova (2023) の視線計測では、掛詞の有無で見られ方の全体の傾向は変わらなかった
- 方針：文字どおりに読んでも意味が通る技法だけ使う

| 前 | 後 | 技法 |
|---|---|---|
| 同じ机　ちがう時間 | 早送りで　見返す | 掛詞：見返す＝もう一度見る／見返してやる |
| 顔は　見せなくていい | 顔は隠して　机は見せる | 対句 |
| 撮った日が　並んでいく | 撮った日を　積み上げる | キャラクター名（つみわら）とつなげる |
| 友達の机にも　灯りがついている | 「がんばれ」を　送り合う | アプリのスタンプ名をそのまま使う（`BuddyProfile.swift`） |
| 今夜の机から | 今夜の　一コマ目を撮る | 掛詞：一コマ＝動画の一コマ／授業の一コマ |

### 文言の効果は未検証。検証するなら（検出力の計算）

- 2案を同じ人に見せて、どちらがよいか選んでもらう（両側の正確二項検定、α=0.05、検出力 80%）：一方が 65% 選ばれる差なら 90 人、70% なら 49 人、75% なら 30 人
- 5秒テストで「何のアプリか」答えられた割合を、2案で比べる（別々の人に見せる）：50% 対 75% の差なら各群 58 人、60% 対 80% なら各群 82 人
- これより少ない人数でも、伝わらない言葉は見つけられる。ただし「どちらがよいか」を統計的に言うことはできない
